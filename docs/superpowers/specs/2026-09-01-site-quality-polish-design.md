# 网站质量与阅读体验优化设计

## 目标

在不改变“豆包工作蓝皮书”内容结构和纯静态部署方式的前提下，缩短首页可见时间，修复阅读与导航闭环，提升子页面的内容层级，并建立能够真实判错的自动化验收。

## 基线结论

- 首页必须下载约 456 KB 的完整正文 JSON 后才显示；模拟 150 ms 延迟、约 1.6 Mbps 下行时，应用可见约需 4.6 秒。
- 二维码库约 56 KB，在任何页面启动时都同步进入关键请求链，但只有生成分享卡片时才使用。
- 版本化 CSS、JS 和内容仍被 `_headers` 标记为 `no-cache`，重复访问不能充分利用浏览器缓存。
- 原“继续阅读”脚本等待时间与翻页动画同为 600 ms，曾在路由真正完成前读到顶部位置；改为等待路由后确认可恢复到页面最大可滚动位置附近。
- 首页“查看目录”测试等待时间短于翻页动画时间，打印了错误路由仍以退出码 0 结束。
- 首页视口外卡片被设置为 `opacity: 0`；全页截图、打印或观察器异常时会出现大片空白。
- README 仍引用已经不存在的 `site/app.js`、`site/styles.css`，并宣称站点有明暗主题切换；站内正式名称已经是“豆包工作蓝皮书”。
- 正文页的文字、图片和表格直接铺在白底上，长内容缺少统一的内容边界与章节视觉索引。

## 设计方向

### 1. 两阶段内容加载

新增由完整内容生成的轻量 `site-index.json`。首页、导读和目录先读取轻量索引并立即渲染；完整正文随后在浏览器空闲阶段后台加载。直接访问文章或用户在正文尚未就绪时打开文章，路由会等待同一个去重后的正文请求并显示清晰的加载状态。

索引保留节点关系、标题、媒体数量和首页摘要，不复制全文。完整 JSON 继续作为公开内容的唯一正文来源，避免维护两份内容。

### 2. 非关键能力按需加载与缓存

二维码库从入口 HTML 移除，仅在用户首次生成分享卡片时动态加载。HTML 保持不缓存；带版本号的 CSS、JS、字体、站内资源和内容 JSON 使用长期缓存。每次展示层发布时统一更新资源版本号。

### 3. 阅读交互闭环

继续阅读恢复滚动必须在新文章 DOM 完成布局后执行，且恢复前不得用顶部位置覆盖已保存值。搜索框补齐组合框语义、结果关联和活动项状态。首页翻页测试等待真实路由变化，不以固定的过短等待代替验收。

### 4. 子页面视觉层级

正文和章节概览统一放入“内容图框”：左右规线、四角注册标记、极淡蓝图纸底纹和顶部内容标签。正文二级标题增加自动章节编号，提示词、图片、表格和 callout 保留现有卡片语言。移动端保留左右边界，但减少内边距，避免压缩正文。

视觉仍以蓝、白、炭黑为主，不引入新的彩色卡片体系，不依赖网络字体，不增加图片资源。

### 5. 可见性与动效

滚动动效只改变位移，不把未进入视口的内容永久隐藏。`prefers-reduced-motion`、打印、观察器不可用和全页截图都必须保持内容可见。

## 验收标准

- 模拟弱网下首页应用可见时间相对当前约 4.6 秒明显下降，首页首阶段不请求完整正文和二维码库。
- 首页、导读、目录、正文、404、搜索、分享、继续阅读、上一节/下一节和页内目录均有自动化断言。
- 58 个内容节点的路由可打开，520 个媒体路径均存在，桌面端与 360/390 px 页面无横向溢出和控制台错误。
- 继续阅读恢复到已保存位置附近，而非顶部。
- 视口外首页卡片的计算透明度为 1；全页截图不再出现由动画造成的空白区。
- 正文在桌面和移动端都有明确内容边框，二级标题存在可见编号，图片、表格和代码块不溢出。
- README 的名称、能力、目录结构、运行与测试命令和实际仓库一致。
